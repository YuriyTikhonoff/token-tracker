# Бекапи

Статус: **пропозиція**. Нічого з описаного ще не реалізовано. English: [backups.md](backups.md).

Як Token Tracker захищає свою базу даних і як під час кожного запуску перевіряє, що захист актуальний.

## Що варто бекапити

| Дані | Де | Якщо втрачено |
| --- | --- | --- |
| База даних | `~/.token-tracker/token_tracker.db` (старіша установка тримає її в `backend/app/`; `token-tracker doctor` скаже, де саме) | Використання відновлює `ingest` з транскриптів Claude Code, якщо вони ще існують. Знімки лімітів, назви акаунтів і вибір акаунта за замовчуванням втрачаються назавжди |
| Події акаунтів | `~/.claude/token-tracker-account-events.jsonl` (або `$CLAUDE_CONFIG_DIR`) | Більше не можна визначити, який акаунт використовував яку сесію. Рядки відкочуються до акаунта за замовчуванням |
| Дані Codex | у тій самій базі | Відновлюються з `~/.codex`, поки він існує |

Не бекапляться: `config.toml` (кілька рядків, легко відтворити), збірка дашборда та все під `~/.claude/projects`, що належить Claude Code.

## Поведінка

```bash
token-tracker backup            # зробити бекап зараз
token-tracker backup --status   # коли був останній, чи він свіжий
token-tracker backup --verify   # повторно перевірити найновіший
token-tracker restore [FILE]    # відновити найновіший (або названий) бекап
```

`token-tracker run` перед `ingest` перевіряє вік найновішого бекапу. Якщо найновіший перевірений бекап старший за `max_age` (за замовчуванням 24 години) або його немає, спершу створюється новий, а потім робота триває. Якщо бекап не вдався, виводиться попередження, і робота триває: проблема з бекапом ніколи не завадить дашборду запуститися.

Перевірка читає найновіший **маніфест**, а не час файлів. Бекап із відсутнім файлом або проваленою перевіркою бекапом не вважається.

## Куди вони потрапляють

```
~/Backups/token-tracker/                # TOKEN_TRACKER_BACKUP_DIR або backup_dir у config.toml
  token-tracker-<UTC timestamp>.sqlite.gz
  token-tracker-<UTC timestamp>.events.tar.gz
  token-tracker-<UTC timestamp>.json    # маніфест: джерело, розмір, sha256, пройдені перевірки
```

Копію поза машиною дає тека, розташована в чомусь, що вже копіюється (Time Machine, iCloud Drive). Token Tracker нічого не вивантажує.

## Як створюється бекап

- База копіюється онлайн-API резервного копіювання SQLite, тож це безпечно, поки дашборд працює, і в режимі WAL. Звичайний `cp` так не можна: він може пропустити закомічені записи.
- Копія перевіряється `PRAGMA integrity_check` до стиснення. Провалена перевірка видаляє копію й повідомляє про помилку; нічого не видаляється зі старих бекапів.
- Зберігання: найновіший за кожен із останніх 7 днів і за кожен із останніх 4 тижнів, усе інше видаляється, і лише після того, як з'явиться новий перевірений бекап. Змінюється через `backup_keep_daily` і `backup_keep_weekly` у `config.toml`.
- Файл блокування в теці бекапів не дає двом запускам бекапити одночасно.

## Відновлення

`token-tracker restore` відмовляється працювати, поки дашборд відповідає на своєму порту (перевизначається `--force`), спершу робить страхувальну копію поточної бази (`...-pre-restore`), потім замінює базу й видаляє застарілі файли `-wal` і `-shm`. Після відновлення виконайте `token-tracker ingest`: він підхопить із транскриптів усе, що новіше за бекап.

Тренування відновлення, щоб один раз спробувати в тимчасовому місці, не чіпаючи реальних даних:

```bash
TOKEN_TRACKER_HOME=/tmp/tt-restore-test token-tracker restore
TOKEN_TRACKER_HOME=/tmp/tt-restore-test token-tracker report --top 3
```

## Налаштування

| Налаштування | Змінна | Ключ `config.toml` | За замовчуванням |
| --- | --- | --- | --- |
| Тека бекапів | `TOKEN_TRACKER_BACKUP_DIR` | `backup_dir` | `~/Backups/token-tracker` |
| Максимальний вік | `TOKEN_TRACKER_BACKUP_MAX_AGE` | `backup_max_age` | `24h` |
| Денних копій | | `backup_keep_daily` | `7` |
| Тижневих копій | | `backup_keep_weekly` | `4` |

## Перенесення старішої бази

Якщо `token-tracker doctor` повідомляє, що база лежить на старому місці (`backend/app/`), зупиніть сервер, виконайте `token-tracker backup`, скопіюйте `token_tracker.db` разом із файлами `-wal` і `-shm` у `~/.token-tracker/`, запустіть знову й видаліть старі файли лише після того, як дашборд покаже дані. Не переносіть файли, поки сервер працює.
